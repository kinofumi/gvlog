# 010 M0 は能力表示ではなく、実素材で MP4 を完成させる縦割り検証にする

日付: 2026-10-08

## 状況
元プランの M0 は「端末能力を表示する画面」だった。Codex のレビュー（指摘 1）で、`canEncodeVideo()` の成功は実ファイルを
最後まで処理できる保証ではなく、最大の成立リスクを M3 まで先送りしていると指摘された。

## 選択肢
1. 能力表示画面を先に作り、動画の処理は M3 で確認する
2. 最初に写真 1 枚と iPhone の縦 HEVC 動画 1 本から 10 秒の無音 MP4 を出し、CapCut に入れるまでを通す

## 決定
2 を採用。回転と HDR の素材も含める。HTTPS の検証環境（plugin-basic-ssl）もここで用意する。
mediabunny の採用はこの検証が通ってから ADR で確定する。

## 理由
通らなければ技術選定からやり直す必要があり、それは早いほど安い。時間規則や HTTPS の問題もこの中で自然に片付く。
