# 025 版の番号は package.json で付け、スプラッシュに出す

日付: 2026-11-19

## 状況

ホーム画面に追加したアプリは、閉じて開き直せば最長 10 分で新しい版になる（Service Worker なし、ファイル名にハッシュ、Pages のキャッシュ 10 分）。
ただし「いま開いているのがどの版か」を利用者も支える側も見分けられなかった。当日に「古い版のままでは」と疑っても確かめようがない。

## 選択肢

1. `package.json` の `version` をビルド時に埋め込み、スプラッシュに出す。版は人が上げる
2. git のコミットの短い ID をビルド時に埋め込む。自動で変わるが、人には読めない
3. ビルドした日時を埋め込む。自動で変わるが、同じ日に 2 回配ると区別できない

## 決定

1 を採る。`vite.config.ts` の `define` で `__APP_VERSION__` に `package.json` の `version` を入れ、`Splash.tsx` の「タップで始める」の下に `v1.0.0` のように小さく出す。
今の版を `1.0.0` とする（イベントで使える状態になっているため）。

## 理由

- 「v1.0.2 ですか？」と聞けば済む。参加者に読める番号がよい。
- 仕組みは Vite の標準の `define` だけ。型は `src/env.d.ts` の 1 行。
- コミット ID は教科書としては読みにくく、日時は同じ日の配り直しで困る。

## 影響

- **公開するたびに `package.json` の `version` を上げる**（`npm pkg set version=1.0.1` など。lockfile も `npm install --package-lock-only` で合わせる）。上げ忘れると古い番号のまま配られるので、プッシュ前の手順に入れる。
  目安: 文言や見た目の直しは 3 つ目（1.0.1）、機能の追加は 2 つ目（1.1.0）。
- vitest の設定は `vite.config.ts` と別なので、`__APP_VERSION__` はテストでは定義されない。Splash をテストするときは `vitest.config.ts` にも `define` を足す。
