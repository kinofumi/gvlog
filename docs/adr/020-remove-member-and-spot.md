# 020 名前とスポットの入力をやめる（ファイル名は日付と時刻で見分ける）

日付: 2026-11-12

## 状況

編集タブの先頭に「名前」「スポット」の入力欄があり、出力ファイル名（`プリセット名_名前_スポット_日付.mp4`）にだけ使っていた。
利用者から「名前とスポットは必要なくなった」との指示。栞（イベントの栞タブ）でスポットは決まっており、各自が入力する意味が薄くなった。

## 選択肢

1. 入力欄だけ消し、モデルの `meta` は空のまま残す（ファイル名は `_member_spot_` の穴埋めになる）。
2. モデルから `meta` を外し、`createProject` と `setMeta`、ファイル名の引数も合わせて整理する。

## 決定

2 を採る。使わない項目をモデルに残すと、教科書で「なぜあるのか」を説明できない。

- `Project.meta` と `setMeta`（projectActions、store）を削除。`createProject(preset)` だけになる。
- ファイル名は `buildFileName(names: string[], date)` にし、`名前_YYYYMMDD_HHMMSS.mp4` の形にする。編集はプリセット名だけ（例: `Vlog_20261112_140509.mp4`）、つなげるは `Vlog_つなげる_...`。
- 名前が無くなると同じ日に作った人どうしのファイル名が同じになり、集めるときに上書きしやすい。そこで時刻（秒まで）を入れて見分けられるようにする。
  時刻は書き出しが終わったときのもの。ExportPanel が `fileNames`（名前の並び）を受け取り、できた MP4 を File にするときに `buildFileName` を呼ぶ（描画時に名前を決めると、素材を選んでから生成するまでの間で時刻がずれ、再生成しても同じ名前になる。レビューの指摘）。
  同じ秒に 2 人が生成すれば同名になる。乱数を足せば防げるが、名前が読みにくくなるのでやらない。集める側は iOS の写真や Files が同名を番号で区別するのに任せる。

## 影響

- プロジェクトの保存形式（IndexedDB）はまだ無いので、移行はいらない。
- plan §2.3（Project 型）と §4（ファイル名）、support-matrix の手順を更新。
