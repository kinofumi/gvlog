# 017 「つなげる」モードは、集めた MP4 を読み直して描き直す

日付: 2026-11-11

## 状況

フィールドテスト後に「グループ全員の動画を集めて順番に並べてつなげるモード」の要望が出た。
各自の MP4 は端末ごとに違うエンコーダ（iPhone / Android / PC）で作られていて、
コーデックのプロファイルやビットレートがそろう保証はない。

## 選択肢

1. MP4 のサンプルをデコードせずに連結する（再エンコード無し。速いが、各端末のストリームを 1 本にまとめる互換性の問題が出る。つなぎの白フェードも入れられない）
2. 集めた MP4 を素材（動画）として読み直し、編集と同じ `exportProject` でフレームごとに描いて再エンコードする

## 決定

2 を採用。

- 4 つ目のタブ「つなげる」（`JoinPanel`）。集めた動画はこの画面の state が持ち、編集タブの素材とは混ぜない。
- `join/joinProject.ts` の `buildJoinProject(clips)` が、各クリップの尺 = 元の動画の長さ（1 秒未満なら 1 秒）、クリップの間 = 白フェード 16 フレーム（ADR 016）の
  `Project` を組み立てる（ID と日時以外は入力だけで決まる）。プリセットは編集と同じ画面サイズ・fps で、上限だけ `JOIN_MAX_FRAMES`（10 分）。
- 書き出しは編集タブと同じ `ExportPanel`（props で `project` / `images` / `videos` / `fileName` を受けるようにした）。
  エンコーダは端末に 1 本なので、どのタブから始めても store の `exporting` で排他する。
- 取り込みは編集タブと同じ `importOneVideo`（`media/importEntries.ts` に移した）。
- プレビューは付けない。並べるのは編集済みの動画なので、順番とサムネイルと合計で足りる。

## 理由

- 2 なら端末ごとのエンコードの差を吸収でき、白フェードも入り、新しいコードは「プロジェクトの組み立て」と「画面」だけで済む。
- 1 は mediabunny で可能だが、互換性の検証が端末の数だけ要り、教科書としても説明が難しい。

## 影響

- 書き出し時間は合計の長さに比例する（15 秒 × 10 人で 150 秒分のデコードとエンコード）。進捗とキャンセルは編集と同じ。
- 集めた動画はメモリ上に置く（ADR 012）。10 本で 100 MB 程度を見込む。削除したら解放する。画面は App が隠すだけで外さない。
- 合計が上限（10 分）を超えた分は出力に入らない。編集タブと同じ赤い注意を出す。
- 取り込み中・書き出し中の印は store のもの（`ui.importing` / `ui.exporting`）を編集タブと共用し、タブをまたいで 1 つずつにする。
- 元の動画が縦でなくても、描画が cover で出力サイズに合わせる。

## 追記（2026-11-11）: 表紙と白フェードアウトの終わり

利用者の要望で、先頭に 3 秒の表紙、最後は白くフェードアウトして終わるようにした。

- 表紙は 1 色（濃い灰色）の写真素材 `join-cover` に、入力欄の文字を中央のテロップ（縁取り）で載せる。文字が空白だけなら表紙は置かない。
- 終わりは白 1 色の写真素材 `join-end`（尺は白フェードの 2 倍 = 32 フレーム。これより短いと白フェードが切り詰められる）。
  最後のクリップから `fadeWhite` でつなぐので、既存の描画と区間計算のまま「白フェードアウトして終わる」になる。
- 表紙と終わりの絵は `join/cards.ts` が 1×1 の canvas で作る（1 色なので描画の cover で引き伸ばせば足りる。出力サイズで作ると 1 枚 8 MB を持ち続ける）。
  `buildJoinProject(clips, coverText)` は素材 ID を固定値で持ち、文字は前後の空白と改行を除いてテロップにする。
- 別案「最後のクリップの transitionOut を『次が無くても白へ』と解釈する」は、compile と render に終端の特例が増えるのでやめた。

## 追記（2026-11-12）: 簡易プレビュー

「プレビューは付けない」としていたが、利用者の要望で、順番・表紙・BGM の雰囲気を確かめるための簡易版を付けた。

- 手順は `join/previewSteps.ts`（純粋関数）が決める: 表紙の止め絵（表紙の真ん中のフレームを `renderFrame` で描く。テロップが出きっている）→ 各動画を順に再生 →
  白い終わりの止め絵。白フェードは出さない。各手順の長さは出力と同じなので、プレビューの長さも出力と同じ。
- 画面は `components/JoinPreview.tsx`。`<video>` は 1 つだけで、1 本終わるごとに次の動画の Blob から Object URL を作って差し替える
  （全員分の `<video>` を同時に持たない。iPhone のメモリと同時再生数の上限を避ける）。素材の音は出さない（出力にも入らない）。
- BGM は `<audio loop>` で流す。再生ボタンの操作の中で始める（iPhone は操作からしか音を始められない）。末尾のフェードアウトは出ない。
  `<video>` は muted + playsInline なので、操作の外（表紙の 3 秒後）からでも再生を始められる。
- 素材や表紙の文字が変わった、曲を変えた、画面が隠れた、書き出しが始まった、のどれでも止まり、戻っても勝手に再開しない
  （「再生していてよい条件の目印」を useMemo で作り、再生の状態に始めたときの目印を持つ。違えば止まっているとみなす）。
- 各手順の長さは出力と同じ `durationFrames`（動画は再生が始まってから数える）。上限（10 分）を超えた分は出力と同じく入れない。
- 再生を始められない（iPhone の低電力モードでは muted でも操作の外から動かせない）ときは、飛ばさずに止めて赤い文で知らせる。
  再生ボタンの操作の中で `<video>` の `play()` を一度呼んでおく（WebKit はこれで、その要素を操作の外からも動かせるようになる）。
- フル機能のプレビュー（編集タブの `usePreview`）を使わなかったのは、store の編集プロジェクトを直接読む作りで、全員分の `<video>` を持つため。
  つなぎ目の白フェードは生成した動画で確かめる。
