# 012 動画は取り込み時にまるごとメモリへ読み込む

日付: 2026-10-09

## 状況
Android 10 / Chrome 154 の実機で、書き出しの途中に `TypeError: network error` が出た。Chrome がファイルを読めなかったときの
エラーで、書き出し中にファイルを読むのは動画だけ（`BlobSource` が必要な範囲を少しずつ読む）。
Android ではファイル選択で渡される File が一時的なアクセス権に基づき、アプリ切り替えや時間経過で読めなくなることがある。

## 選択肢
1. `BlobSource` のまま、読めなくなったら「選び直してください」と案内する
2. 取り込み時に `file.arrayBuffer()` でまるごと読み、`BufferSource` で扱う。ファイル上限を 500 MB から 200 MB に下げる

## 決定
2 を採用。読み取りに失敗したら取り込みの時点で `MediaError` にする。

## 理由
読めない素材は選んだ直後に分かるほうが、書き出しの最後で失敗するより分かりやすい。
書き出し中にファイルを読む経路がなくなるので、失敗の原因が 1 つ減る。
代わりにメモリが動画サイズ分増えるが、10 秒素材に使う動画は数十 MB で、200 MB の上限で足りる。
M4 で IndexedDB に保存するときも、保存した Blob から同じように読み直せる。

## 補足（2026-10-14、M3(B)）
読み込んだデータは `ArrayBuffer` のままではなく、メモリ上の `Blob` にして持つ。デコード（`BlobSource`）とプレビューの `<video>`
（`URL.createObjectURL`）で同じデータを使うため。`BufferSource` + 別の Blob にすると動画サイズの 2 倍のメモリになる。
メモリ上の Blob は Android の File と違って読めなくならない。
