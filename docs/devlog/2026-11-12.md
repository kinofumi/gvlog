# 2026-11-12

- 「つなげる」に BGM（ADR 019、ブランチ `join-bgm`）。利用者の決定は「つなげるだけ」「曲は後で渡す。それまで仮の曲」。
- 調べたこと: 音声を MP4 に入れるには AAC へのエンコードが要り、iPhone の Safari は WebCodecs の AudioEncoder に iOS 26 から対応。
  デコードせずに AAC のパケットをコピーする案はフェードアウトができないのでやめた。
- 仮の曲は Python（numpy なし、wave モジュール）で正弦波の和音 + ベース + アルペジオを合成し ffmpeg で MP3 に（scratchpad の synth.py）。
- 純粋関数 `bgm/loop.ts`（ループ、末尾 2 秒フェード、サンプル数）をテストファースト。`exportFrames` は映像のあとに BGM を 1 秒ずつ足す（テストはフェイクの AudioBuffer）。
- `AudioBuffer.copyToChannel` が `Float32Array<ArrayBuffer>` を要求して型が合わなかったので `getChannelData(c).set(...)` に。
- JoinPanel が 270 行を超えたので BGM の状態を `bgm/useBgm.ts` に切り出した。
- 二重レビュー（`docs/reviews/2026-11-12-bgm.md`）。大きいのは「ステレオの曲だと対応確認（1 ch）と実際（2 ch）がずれる」で、BGM はモノラルにそろえた。
  落とし穴: ffmpeg の `-ss` + `volumedetect` で末尾の音量を測ると下がって見えず、WAV にして 0.5 秒ごとに RMS を出したら正しくフェードしていた。
- つなげるに簡易プレビュー（ADR 017 追記）。`<video>` 1 つで順に差し替え、BGM は `<audio loop>`。表紙の止め絵は最初フレーム 0 を描いていてテロップが薄かった
  （フェードインの途中）ので、素材の真ん中のフレームにした。JoinPanel が 200 行を超えたので一覧を `JoinClipList` に切り出した。
