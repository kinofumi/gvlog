## Codex（2 件、ゲート PASS）
- [P2] 行数が増えるとセーフマージンを破って画面外へ出る（ブロック高に上限がない）。
- [P2] 明示的な空行（連続改行、先頭・末尾の改行）が消える。

## Claude `/code-review main..HEAD high`（8 件）
1. panLR / panRL の cx 範囲（0.35→0.65）が zoom 1.15 で空く余白（±0.065）を超え、出力と同じ縦横比の写真では端で止まって「静止 → 急にスライド → 静止」になる。
2. `wrapText` がコードポイント単位で分割し、結合文字や ZWJ 絵文字を分断する。`\r` も残る。
3. 行数が多いと画面外へはみ出す（Codex 1 と同じ）。
4. `captionAlpha` の入りと出が非対称（最初のフレームが常に 0）。
5. `kenBurnsPreset` の switch に default がなく、未知の presetId で undefined。
6. `layoutCaption` が返す `maxWidth` は折り返しの前に必要な値で、返しても使えない。
7. 0〜1 のクランプが 3 か所で重複。
8. plan §1 / §3.2 のファイル名（`timeline/easing.ts`、`render/wrapText.ts`）が実装と違う。

## 人間の判断
- すべて採用。
  - 1: パンの振れ幅を `(1 − 1/zoom) / 2` から導く。どの写真でも端に当たらず一定の速さで動く。plan §3.2 に理由を追記。
  - 2: `Intl.Segmenter`（書記素）で分割。`\r\n` を `\n` に揃える。
  - 3: `maxCaptionLines` で収まる行数を計算し、超えた行は切り捨てて `overflow: true` を返す（文字サイズはグループで揃えるため変えない）。
  - 4: 入りを `(frame − showStart + 1) / 8` にして対称に。最低表示長 16 フレームで山が 1 に届く。
  - 5: switch を `Record` の表にして、未知の値は none に倒す。
  - 6: `captionMaxWidth(canvasWidth)` を export し、`CaptionLayout` から外す。
  - 7: `render/clamp01.ts` に切り出し。
  - 8: plan §1 と §3.2 を実装に合わせる。
- Codex 2（空行）: 採用。入力全体が空のときだけ 0 行。

## 学び（教科書向けメモ）
- 「正規化座標の中心 ± 定数」のような設定値は、別の入力（写真の縦横比）で破綻しないか考える。レビュアーは別の縦横比で計算していた。
- 文字列を「1 文字ずつ」扱うときは、コードポイントではなく書記素（`Intl.Segmenter`）。
