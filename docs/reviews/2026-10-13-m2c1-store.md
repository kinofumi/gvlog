# 2026-10-13 M2(C1) プロジェクト操作と zustand ストアの二重レビュー

対象: `main..m2-store`（`state/projectActions.ts`、`state/store.ts`、テスト 19 件）。

## Codex（3 件、ゲート FAIL）
- [P1] 同じ ID の再追加で素材が二重登録され、画像辞書は上書きされて旧画像がリークする（再現して close 回数 `[0, 1]` を確認）。
- [P2] 変更不能な操作（動画への Ken Burns、同じ位置への移動）でも新しい Project を返し、同一性の約束が破れる。
- [P2] `seek` が NaN や小数をそのまま保存する。

## Claude `/code-review main..HEAD high`（7 件）
1. 同じ ID の再追加（Codex P1 と同じ）。
2. `seek` の整数化と NaN（Codex と同じ）。
3. 末尾の素材への `setTransition` は切り詰められず、上限超え・小数・負がそのまま保存される。
4. 変化のない操作（同じ位置への移動、無いキャプションを外す、同じ値のトランジション）でも `updatedAt` が進む（Codex と同じ系統）。
5. `setMeta` だけが純粋関数を経由せず、渡されたオブジェクトを参照で持つ。
6. 追加・削除で均等割りに戻すため、手動調整した尺が失われる。plan に判断がない。
7. モジュール読み込み時に `crypto.randomUUID()` を呼び、LAN の http で開くと白画面になる。

## 人間の判断
- Codex P1 / Claude 1: 採用。`addPhoto` は重複 ID を拒否。store は拒否された新しい画像だけ閉じ、既に持っている画像は閉じない。テスト追加。
- Codex P2 / Claude 4: 採用。`updateItem` は変更関数が元の素材を返したら Project も元のまま。`moveItem` は同じ位置なら元のまま。
  `setKenBurns` / `setCaption` / `setTransition` も同じ値なら元のまま。
- Codex P2 / Claude 2: 採用。`seek` は非有限値を無視し、整数に丸めて範囲に収める。
- Claude 3: 採用。`setTransition` は長さを 0 以上の整数に整えてから保存する（末尾でも保存し、素材を足したときに上限で切り詰める）。
- Claude 5: 採用。`projectActions.setMeta` を作り、store はそれを呼ぶ。
- Claude 6: **設計は変えず、plan §2.2 に v1 の割り切りとして記録**。「写真を全部入れてから尺を調整する」流れを想定。
  調整を保つ配分は、必要になったら後の章で足す。
- Claude 7: 採用。`model/ids.ts` の `newId()` で `randomUUID` が無ければ乱数で代用。

## 2 者の比較
- 両方が指摘: 重複 ID（Codex は再現して close 回数まで確認）、同一性、seek。
- Claude だけ: 末尾トランジション、`setMeta`、手動調整の消失、非セキュアコンテキスト。
- Codex は P1 として重複 ID を最重要に置き、Claude は 7 件を並べた。重なりが 3 件と多く、ストア層は観点が揃いやすい。

## 学び（教科書向けメモ）
- 「変えられないときは元を返す」と決めたら、すべての経路でそれを守る。守れているかはテストの `toBe` で確かめる。
- 画像のような資源は「誰が閉じるか」を store の 1 か所に集め、拒否経路でも閉じ忘れない。
- `crypto.randomUUID` のように環境で無い API は、モジュールの読み込み時ではなく関数の中で使う。
