# 2026-10-14 動画の終了位置（尺に連動）の二重レビュー

対象: `main..trim-end`（`timeline/durations.ts` の `maxItemFrames`、`timeline/trim.ts` の `trimEndRange`、`projectActions.setTrimEnd`、store、
`TrimEditor` の 2 本目のスライダー、plan §2.3）。設計は ADR 014。

## Codex（P2 が 3 件、P3 が 1 件）
- [P2] 表示した終了位置より後の映像が再生される。終了位置は開始位置 + 尺だが、再生はトランジション込みの見える長さだけ進む。
  元動画が尺以上・見える長さ未満のときのホールドも新しい注意書きの条件では出ない。
- [P2] `trimEndRange` の `extra` を変更前の値で固定している。尺を縮めればトランジションも縮んで有効になる終了位置まで操作不能にする。
- [P2] `setTrimEnd` が「開始位置は変えない」契約を守らない。UI の上限に依存し、アクション単体では `clampTrims` が開始位置を手前に戻す。
- [P3] 終了位置スライダーの値が範囲外になり、つまみと数値表示が食い違う（元動画が短いとき）。

## Claude `/code-review main..trim-end high`（7 件）
1. 元動画が尺より短いとき、終了位置スライダーの value が元動画の末尾に切り詰められ、触れただけで尺が黙って縮み元に戻せない（Codex 4 と同じ）。
2. `setTrimEnd` が開始位置を動かしうる（Codex 3 と同じ）。
3. 「最後のフレームで止まります」の条件が狭まり、トランジション由来のホールドで出ない。「〜秒までを使います」も実際より少なく表示（Codex 1 と同じ）。
4. 無関係な `docs/manual/QRpng`（拡張子なしの PNG）がコミットに混入している。
5. Tailwind の「同じクラスの組み合わせを 3 回以上書いたら切り出す」に違反（フレームのスライダー＋秒表示が 4 か所）。
6. 「終了位置は保存せず尺に連動させる」設計判断の ADR がない。
7. `canChangeDuration={items.length > 1}` は「素材 1 つなら尺は固定」の知識の 3 か所目。

## 人間の判断
- Codex 3 / Claude 2: 採用。`setTrimEnd` が `compileTimeline` と `trimEndRange` で上限を求めてから尺にする。末尾超えとクロスフェード付きのテストを追加。
- Codex 4 / Claude 1: 採用。終了位置（開始位置 + 尺）が範囲の外（= ホールド中）ならスライダーを無効にし、範囲内に収めた値だけ渡す。
  「尺は素材一覧のスライダーで変えられます」と案内。
- Codex 1 / Claude 3: 採用。「〜秒までを使います」は見える長さで計算した実際の範囲に戻し、クロスフェードがあれば
  「終了位置より先も使います」と添える。ホールドの注意書きは「終了位置が上限を超えている」で判定（トランジション由来も拾う）。
- Claude 4: 採用。`git rm --cached` でコミットから外した（ファイルは作業ツリーに残す。利用者が置いたもの）。`git add -A` の注意点として記録。
- Claude 5: 採用。`FrameSlider`（スライダー＋秒表示）を切り出し、尺・クロスフェード・開始位置・終了位置の 4 か所で使う。
- Claude 6: 採用。ADR 014 を追加。
- Codex 2: **不採用**。そのケース（元動画が 1.3 秒で 2 秒のクロスフェード）はホールド中なのでスライダーは無効になり、尺は一覧のスライダーで縮められる。
  変更後のトランジションまで見て範囲を決めると、UI と純粋関数の両方が「仮に縮めたら」を計算することになり、平易さに見合わない。
- Claude 7: **不採用**。`maxItemFrames(1, total) === total` から無効化を導くと、他の素材が全員最小尺で尺が上限に達した場合と区別できない。明示的な条件のほうが読める。
- 記録: `projectActions.ts` が 222 行になった（200 行超）。M4 で保存・復元の操作が増えるときに分割を検討する。

## 2 者の比較
- 両方: `setTrimEnd` の契約違反、短い動画でスライダーの値が範囲外、表示と実際に使う範囲のずれ。3 件とも実装の本質的な穴で、2 者が独立に同じ場所を突いた。
- Codex だけ: 「縮めれば有効になる」境界（深いが、平易さとの釣り合いで不採用）。
- Claude だけ: 混入ファイル、Tailwind 規則、ADR、重複した知識。リポジトリの約束（CLAUDE.md）に照らす指摘は Claude が強い。

## 修正後の確認
- lint / typecheck / 223 件のテスト通過。
- ヘッドレス Chrome（10 秒の色が変わる動画＋写真）: 開始 3.0 秒・終了 7.0 秒で尺 4.0 / 6.0 秒、プレビューの 0 / 60 / 119 フレームが黄 / シアン / 白、120 フレームで写真の赤。
  書き出しの 0 / 3.9 / 4.1 / 9.9 秒が黄 / 白 / 赤 / 赤。クロスフェードを付けると上限が 8 フレーム縮み（292）、末尾まで使っても開始位置は 3.0 秒のまま。
  2 秒の動画を足すと終了位置は無効で「最後のフレームで止まります」が出る。コンソールエラーなし。

## 学び（教科書向けメモ）
- 純粋関数の契約（「開始位置は変えない」）を UI の範囲チェックに頼らせない。関数自身が範囲を求めて守る。
- スライダーには範囲内の値だけ渡す。範囲外の値を渡すと、つまみと表示がずれ、触っただけで状態が変わる。
- `git add -A` は作業ツリーにある無関係なファイルも拾う。コミット前に `git status` を見る。
